## 二、阶段 1：数据库改造（P0）

### T1-1 修改 `db/schema.sql`

三张表都只做**加字段**，不改主键、不改唯一约束、不改外键。
`uk_reg_student_activity (activity_id, student_id)` **保持不变**（见 6.1 说明）。

```sql
-- ① user：新增账号状态；role 的取值扩展为 STUDENT / TEACHER / ADMIN
--    注意 role 是 VARCHAR(20) 没有 CHECK 约束，加 ADMIN 不需要改结构，只改注释
ALTER TABLE `user`
    ADD COLUMN status VARCHAR(20) NOT NULL DEFAULT 'ACTIVE'
        COMMENT '账号状态：ACTIVE 可用 / DISABLED 已停用' AFTER role;

-- ② activity：新增人数上限与参加条件
ALTER TABLE activity
    ADD COLUMN capacity    INT          NULL COMMENT '可接待人数上限，NULL 表示不限制' AFTER end_time,
    ADD COLUMN eligibility VARCHAR(500) NULL COMMENT '参加条件（自由文本），NULL 表示无特殊条件' AFTER capacity;

-- ③ activity_registration：新增审核时间（同时是候补排序依据）
ALTER TABLE activity_registration
    ADD COLUMN review_time DATETIME NULL
        COMMENT '审核时间（也是进入候补队列的时间，候补按此升序）' AFTER register_time;

-- ④ 历史数据迁移：V1.5 没有审核环节，原有报名视为已确定参加
UPDATE activity_registration SET status = 'CONFIRMED' WHERE status = 'REGISTERED';
```

同时更新 `status` 字段的注释，写入新的 5 个取值。

| 改 | `COLUMNS` 加 `review_time`；`mapRow()` 读取 | —— |

| 新增 | `updateStatusAndReviewTime(Long activityId, Long studentId, String status, LocalDateTime reviewTime)` | 审核：一次写入新状态 + 审核时间 |
| 改 | `countRegistered()` 语义调整 | 改为统计 `CONFIRMED`（原来统计 `REGISTERED`） |

> **为什么用 `review_time` 而不是 `register_time` 排序**：
> T2 要求按「**进入候补的时间**」排队，而进入候补发生在**教师审核通过**的时刻，
> 不是学生报名的时刻。两者可能相差很久（报名早但审核晚的人应当排在后面），
> 所以必须单独记录审核时间。

## 四、阶段 3：业务层（P0）

### T3-1 `AuthService`：停用账号不能登录

**设计决定（改动最小的做法）**：`login()` 的签名**不变**，仍返回 `User`。
两条失败路径可以清楚区分：

| 情况 | `login()` 返回 | 调用方处理 |
| --- | --- | --- |
| 账号不存在 / 密码错误 | `null` | 错误码 **2001** |
| 密码正确但账号已停用 | `User`（`status = DISABLED`） | 错误码 **2003** |

由调用方（`AuthApi` 与控制台 `MainMenu`）在拿到 `user` 后检查 `status`。
这样不需要改 Service 签名，控制台入口也能复用同一判断。

### T3-2 `ActivityService`：人数上限与参加条件的校验

| 方法 | 改动 |
| --- | --- |
| `publish()` | 校验 `capacity`：允许 `null`（不限）；非空时必须是正整数，否则返回原因 |
| `update()` | 同上；`eligibility` 限制在 500 字以内 |
| `detail()` / `listAll()` / `listByTeacher()` | 返回的对象已带新字段，无需额外改动 |

### T3-3 `RegistrationService`（本轮改造重点）

| 方法 | 改动 |
| --- | --- |
| `register()` | ① 初始状态由 `REGISTERED` 改为 **`PENDING_REVIEW`**；<br>② "不能重复报名"的判断改为：**存在任何非 `CANCELLED` 的记录**即拒绝（原来只判断 `REGISTERED`）；<br>③ 曾取消过的仍**复用原行**（保持 V1.5 行为，唯一约束不变） |
| `cancel()` | 允许从 `PENDING_REVIEW` / `WAITLISTED` / `CONFIRMED` 取消；不从 `REJECTED` / `CANCELLED` 取消 |
| **新增** `review(activityId, studentId, teacherId, approve)` | 审核。校验活动归属与当前状态必须是 `PENDING_REVIEW`；<br>`approve = false` → `REJECTED`；<br>`approve = true` → 若 `capacity == null` 或 `count(CONFIRMED) < capacity` → `CONFIRMED`，否则 → `WAITLISTED`；<br>**两种情况都写入 `review_time`** |
| **新增** `promote(activityId, studentId, teacherId)` | 候补递补。校验归属；必须是 `WAITLISTED`；必须存在空位（否则错误码 3006）；成功则置为 `CONFIRMED` |
| `activityRoster()` | 改为返回该活动**全部非取消**的报名记录，由前端按状态分组 |
| `countRegistered()` | 改为统计 `CONFIRMED` |
| **新增** `countByStatus(activityId, status)` | 供接口层返回"已确定 / 候补 / 待审核"三个人数 |
| `hasRegistered()` | 改为"存在非 `CANCELLED` 的记录" |

### T3-4 新增 `service/AdminService.java`

| 方法 | 用途 |
| --- | --- |
| `listAllActivities()` | 转发 `ActivityDAO.findAll()`（只读监督视图，US-11） |
| `listAllUsers()` | 转发 `UserDAO.findAll()`（US-12） |
| `disableUser(Long userId, Long operatorId)` | 停用；**不能停用自己**；已是 `DISABLED` 则提示 |
| `enableUser(Long userId)` | 恢复为 `ACTIVE` |

## 五、阶段 4：接口层（P0）

### T4-1 新增错误码

| 错误码 | 含义 |
| --- | --- |
| 2003 | 账号已被停用 |
| 3005 | 报名记录当前状态不允许该操作（如审核一条已取消的报名） |
| 3006 | 没有空余名额，无法递补 |

### T4-2 `RequestContext`

### T4-3 ~ T4-5 改造已有接口

| 接口 | 改动 |
| --- | --- |
| `POST /api/auth/login` | 密码正确但 `status = DISABLED` → 错误码 **2003** |
| `GET /api/auth/me` | 返回体增加 `status` 字段 |
| `POST /api/activities`、`PUT /api/activities/{id}` | 接收 `capacity` / `eligibility` |
| `GET /api/activities`、`GET /api/activities/{id}` | 返回体增加 `capacity` / `eligibility` / `confirmedCount` |
| `GET /api/activities/{id}/registrations` | 返回体按 `pendingReview` / `waitlisted` / `confirmed` 分组，并带三个人数 |

### T4-6 新增 7 个接口

| 方法 | 路径 | 说明 | 角色 |
| --- | --- | --- | --- |
| PUT | `/api/activities/{id}/registrations/{studentId}/approve` | 审核通过 | 教师（须为该活动发布者） |
| PUT | `/api/activities/{id}/registrations/{studentId}/reject` | 审核驳回 | 教师（同上） |
| PUT | `/api/activities/{id}/registrations/{studentId}/promote` | 候补递补 | 教师（同上） |
| GET | `/api/admin/activities` | 全部活动（只读监督） | 管理员 |
| GET | `/api/admin/users` | 全部用户账号及状态 | 管理员 |
| PUT | `/api/admin/users/{id}/disable` | 停用账号 | 管理员 |
| PUT | `/api/admin/users/{id}/enable` | 恢复账号 | 管理员 |

> **管理员调用报名相关接口必须返回 403**（US-14）：
> 管理员**不在**这三个审核接口的允许角色里，`requireRole("TEACHER")` 会自动拦截。

### T4-7 `ApiVo` 视图对象
