### 1.3 三个设计原则

| 原则 | 做法 |
| --- | --- |
| **可反复运行** | 每个测试类自带数据清理：临时插入的活动/账号/报名记录测完就删，改过的数据会还原。连跑多次不会累积垃圾数据，也不会因为"上次残留"而误报失败 |
| **不依赖精确演示数据** | 断言用 `>=` 而不是 `==`；按标题而不是写死 id 找活动；需要构造场景时**自建临时数据**，不依赖 `schema.sql` 里的具体记录 |
| **断言而不是打印** | V1.0 的三个 DAO 测试原来只打印结果让人眼看（技术债 T6），本轮全部改成断言式，末尾直接给出通过/失败计数与结论 |

## 三、测试中发现的问题及修正情况

> 这一节是报告第十节明确要求的。下面三个问题都是**真实发现**，不是编的。

### 3.1 ★ 两个 DAO 测试会破坏演示数据（严重）

| 项目 | 内容 |
| --- | --- |
| **发现时机** | 阶段 3 跑测试时，新加的 `DaoV2SmokeTest` 在**批量连跑**时失败，单独跑却是通过的 |
| **现象** | 断言「findAll() 返回 6 个用户」实际返回 8 个；「活动4 存在」失败；活动2 的人数统计不对 |
| **排查过程** | 先怀疑新测试依赖了精确的演示数据（确实是原因之一），但在核对数据库时发现更严重的事：演示活动「书法体验课」**整个不见了**，报名记录也少了一条 |
| **根因** | `ActivityDaoTest` 和 `RegistrationDaoTest` 都用「取列表最后一条」来定位自己刚插入的活动：<br>`activities.get(activities.size() - 1)`<br>但 `findAll()` / `findByTeacherId()` 是**按 `start_time` 排序**的，不是按插入顺序，所以"最后一条"根本不是刚插入的那条 —— 而是开始时间最晚的**演示活动** |
| **实际后果** | `ActivityDaoTest` 把演示活动「书法体验课」改名、关闭并**删除**；<br>`RegistrationDaoTest` 把学生的报名记录写到了演示活动「校园歌手大赛」上，清理时**删掉了李同学在该活动的正式参加记录**，随后删活动被外键拦住 |
| **修正方式** | 改用 `insert()` **回填的自增主键**定位（阶段 2 已经实现了 `RETURN_GENERATED_KEYS`，这两处过时的 workaround 本来就该删掉）：<br>`Long newId = activity.getId();` |
| **同时加固** | 两个新测试不再依赖精确的演示数据：用户数用 `>=`、按标题而不是写死 id 找活动、报名相关的断言全部改为**自建临时数据** |
| **验证** | 重跑 `schema.sql` 恢复演示数据后，**连续跑两轮全部测试**，两轮均 0 失败，且演示数据完好 |

> **这条的普遍意义**：把"列表最后一条"当成"我刚插入的那一条"是**逻辑错误**，
> 而且它不会报错 —— 只会静默地操作错对象。列表是按**业务字段**排序的，
> 和插入顺序没有任何关系。教训是：**能拿到确切标识（自增主键）时，绝不要靠位置去猜**。

### 3.2 测试类互相污染数据库（技术债 T6 / T7）

| 项目 | 内容 |
| --- | --- |
| **现象 1** | `UserDaoTest` 插入了测试账号 `test_user_01` 却从不清理。**第二次运行**时插入直接抛唯一约束异常，断言结果全部失真 |

### 3.3 控制台中文乱码，一度被误判成代码 bug

| 项目 | 内容 |
| --- | --- |
| **现象** | 跑测试时控制台输出的中文全是乱码 |
| **误判** | 第一反应是"代码里有编码问题"，花时间检查了源文件编码 |
| **真正原因** | **Java 的 `System.out` 在输出被重定向时使用操作系统的本地编码（GBK）**，而 PowerShell 按 UTF-8 解码，两边对不上。与项目代码无关 |
| **修正方式** | 在 `build.bat` 的 `java` 命令里加上 `-Dstdout.encoding=UTF-8 -Dstderr.encoding=UTF-8`。这是**环境问题**，不是功能缺陷，但写进 `build.bat` 后中文日志就正常了 |
| **附带教训** | 同一时间还遇到 `build.bat` 因为**换行符变成 LF** 而被 `cmd` 解析错乱（批处理文件必须是 CRLF）。这两个问题都表现为"程序行为异常"，但根因都不在业务代码里 —— 排查时应当先确认**是代码问题还是环境问题** |
