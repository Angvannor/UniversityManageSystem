# 学生角色 · 补充访谈提纲

> **为什么补访**：第一轮访谈中学生角色只拿到 2 条有效回答，
> 且 S1 完全没有回答「怎么知道有哪些活动」，导致 G2 悬空。
> 学生视角目前仅由 S2（热门活动报不上）单条支撑，需要补强。
>
> **对应缺口**：G2 为主，同时从学生侧验证 REQ-V2-03 / 06 / 07 / 10。
>
> **用法**：运行 `软件工程实验2：模拟需求访谈.exe`，先选「学生用户」角色，
> 然后依次提问。问到的**逐字记到下面的记录表里**；问不到的不要编，
> 继续留在 `需求提取.md` 的待确认清单中。

## 回填指引

补访完成后，按下面三处回填，保持文件之间不打架：

| 回填到哪里 | 做什么 |
| --- | --- |
| `访谈记录.md` → 一、学生用户 | 把新问答并入表格（序号接着排 S3、S4…），并同步更新「访谈规模」表的条数 |
| `访谈记录.md` → 学生小结 | 重写小结（原小结已说明覆盖度最弱，补访后应更新） |
| `需求提取.md` → 第四节待确认清单 | 把已问到答案的 G2／G3 等移出待确认表，或把结论补进去 |
| `需求提取.md` → 第一节候选需求表 | 若补访证据支持或推翻了某条候选需求，更新对应行的「访谈证据」与「最终结论」 |

> ⚠️ **不要为了让表格好看而补写没问到的内容。**
> 报告模板明确要求「没有发生的内容不要补写」，
> 而且第十二节专门要问「哪些需求是通过追问或跨角色确认后才明确的」——
> 留下的缺口本身就是要写进报告的素材。
